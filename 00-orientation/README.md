## 1. 경영학 지도에서 "인사조직"은 어디에 있는가

경영학(Business Administration)은 보통 아래처럼 나뉩니다 (나무위키 경영학 문서 기준 세부전공 분류).

| 분야 | 다루는 것 | 컴공 관점 비유 |
|---|---|---|
| 회계학 | 돈의 흐름을 기록·보고 | 로깅(logging) + 감사(audit trail) |
| 재무관리 | 자금 조달·투자 의사결정 | 자원 할당(resource allocation) 최적화 |
| **인사조직** ← 우리가 갈 곳 | 사람과 조직 구조를 관리 | 분산 시스템의 노드(사람) 관리 + 오케스트레이션 |
| 마케팅 | 고객에게 가치를 전달 | 프론트엔드 + 사용자 경험(UX) |
| 생산/서비스운영관리 | 제품·서비스를 효율적으로 생산 | 파이프라인 최적화 |
| 정보시스템(MIS) | 기업의 정보 인프라 | 백엔드 인프라 그 자체 (컴공생에게 가장 익숙한 영역) |
| 경영전략/국제경영 | 회사 전체의 큰 그림 | 시스템 아키텍처 설계 |

즉 인사조직관리는 "회사라는 시스템에서, **사람(가장 예측 불가능한 컴포넌트)** 을 어떻게 설계·배치·관리할 것인가"를 다루는 분야입니다.

## 2. 컴공생을 위한 비유로 빠르게 감 잡기

이 비유들은 정확한 학술적 대응은 아니지만, 처음 개념을 잡는 데 유용합니다.

- **조직행동론(OB)** ≈ 개별 노드(사람)의 동작 원리를 이해하는 것. 왜 어떤 사람은 특정 인풋(보상, 피드백)에 다르게 반응하는가 — 마치 같은 API 호출에도 서버마다 다른 latency가 나오는 이유를 프로파일링하는 것과 비슷합니다.
- **조직구조론/조직설계** ≈ 시스템 아키텍처. Monolith(기능별 조직, functional structure)로 갈 것인가, Microservice(사업부제, divisional structure)로 갈 것인가, 그 중간(매트릭스 조직)으로 갈 것인가 — 트레이드오프가 존재합니다.
- **인적자원관리(HRM)** ≈ 리소스 프로비저닝 + 라이프사이클 관리. 채용(provisioning) → 온보딩(initialization) → 평가(monitoring) → 보상(scaling) → 퇴사(deprovisioning).
- **리더십** ≈ 오케스트레이터/스케줄러. 단순히 명령을 내리는 게 아니라, 팀이 스스로 잘 동작하도록 컨텍스트와 우선순위를 설정하는 역할.
- **노사관계론** ≈ 프로토콜과 계약(SLA). 노동자-사용자 관계를 규율하는 규칙의 집합.
- **조직문화** ≈ 코드 컨벤션/암묵적 합의. 명문화되지 않았지만 모두가 따르는 규칙.

비유는 여기까지만 — 실제 학습은 사람은 서버가 아니라는 전제에서 출발해야 합니다. 이 지점이 경영학이 어려운 이유이자 재미있는 지점입니다: **변수가 통제되지 않는 시스템을 이해하는 것.**

## 4. 학습법 제안 (능동적 학습)

경영학 강의는 CS 강의와 달리 "정답이 있는 문제 풀이"가 적고, 프레임워크로 현실 사례를 해석하는 연습이 많습니다. 그래서:

1. **강의를 보기 전, 소제목만 보고 스스로 예상 답을 적어본다** (예: "동기부여 이론이 뭘까?" → 내 생각 먼저)
2. **케이스/이론을 배우면 반드시 아는 회사·조직 사례에 적용해본다** (다니는 회사, 관심 스타트업, 심지어 동아리도 좋음)
3. **각 학기 말에 배운 내용을 1페이지로 요약**해서 해당 학기 폴더에 커밋 — 이게 쌓이면 나만의 교재가 됩니다
4. 이론은 "암기"가 아니라 "렌즈(lens)"로 취급 — MIT의 `15.311 Organizational Processes` 강의가 강조하듯, 같은 조직 문제도 전략적 설계 관점/정치적 관점/문화적 관점으로 각각 다르게 보일 수 있다는 걸 체득하는 게 핵심입니다.
